XCL - modified build 7
======================

This is NOT an official XCL release. It is XCL (https://github.com/ivall/xcl, GPL-2.0-only)
built from upstream commit 2abc562 (2026-11-23) plus the local changes listed below. The
complete source of this build is at https://github.com/theaustinayers/xcl (tag v0.1.0-mod.7,
branch modified-build). The licence is in LICENSE.txt, third-party notices in THIRD_PARTY.md.

What changed since build 6
--------------------------
- The base is upstream's newer main. It contains, taken by the upstream maintainer from this
  fork's pull request ivall/xcl#195: index / vertex buffers outside unified memory mirrored and
  synced per draw, rect lists drawn as two triangles, memory for committed textures, debug
  layer logging per message id. It also contains upstream's own work on depth views, video
  memory (target pages instead of arenas) and lazily committed physical pages, and the Intel
  CPU instruction emulation (#151). This fork's own versions of those changes are gone.
- Menu text: a small render target the title fills from the CPU (its glyph caches: 256x256 R8
  with the render-target flag) is kept in step with the title's memory. Before, the menus'
  body text was missing most of its letters. Sent upstream as ivall/xcl#211.
  XCL_SYNC_SMALL_TARGETS=0 turns it off.
- Keyboard: Page Up / Page Down hold the right stick up / down, to scroll long menu text.
- DirectStorage: BCPack requests XCL refuses (it has no decoder) are counted in the log.
  XCL_BCPACK_DECODER=<program or .py> hands each chunk to an external decoder the user
  supplies. Experimental; nothing of such a decoder is part of XCL.

Local changes carried from earlier builds
-----------------------------------------
- Launcher menu: "Add a game folder..." picks the folder with a game's unpacked files.
- Keyboard / mouse: the mouse is taken only by a click inside the picture and released by F8,
  by the title bar / borders and by switching windows, so the window can be moved and resized.
- Shader compiler: each DXC compile thread allocates from a heap of its own instead of the
  process heap, so compiles of very large programs run in parallel instead of taking turns.
- Installer (installer/xcl.iss): per-user setup that bundles dxcompiler.dll and dxil.dll from
  the Windows SDK next to xcl.exe, option to set XCL_NETWORK=0.
- build.ps1, BUILDING.md and a GitHub Actions workflow that builds the installer from the
  release tag and attests its provenance.

What this is and is not
-----------------------
- It contains no game files, keys or shader caches. You need your own unpacked game files.
- Windows 10/11 x64, a Direct3D 12 GPU with Shader Model 6.6 and mesh shaders, and the Xbox
  "Gaming Services" component (System32\xgameruntime.dll) are required.
- XCL is developed on AMD GPUs. On NVIDIA GPUs the driver's shader compiler is slow on XCL's
  translated programs; first runs of a large game can sit on a black window for a long time
  while shaders compile. Compiled shaders are cached, so later runs get further.
- It is unsigned. Windows Defender may flag xcl.exe heuristically (it loads and runs another
  program's code inside itself); it then needs a folder exclusion to run.
- A game runs as native code with no sandbox. Only run game files you trust.
